## 一、背景与约束

### 用户与定位

面向长时间专注写作、整理技术文档、绘制结构图的桌面用户。产品承诺「安静、现代、本地优先」，直接读写标准 Markdown 文件，不上传文档内容，无账号、无遥测。

### 已核实的现状（2026-09-29 实测，非推测）

| 项 | 实测结果 | 影响 |
| --- | --- | --- |
| 未发布成果 | Mermaid 放大查看功能（含 5 个新测试，总计 24 测试通过） | 应尽快发版 |
| 文件写入 | `src-tauri/src/lib.rs:53` 使用裸 `fs::write` | 非原子写，断电/崩溃可能截断文件 |
| 分发配置 | `tauri.conf.json` 无 `fileAssociations` | 无法双击 `.md` 打开 |
| 插件 | 无 `single-instance`、无 `updater` | 多开互相覆盖；无自动更新 |
| 性能隐患 | `MarkdownEditor.vue:240` MutationObserver 监听 editorRoot 整棵子树 | 每次 DOM 变动触发 `querySelectorAll` 与属性写入 |
| Mermaid 渲染 | 每次渲染调用 `mermaid.initialize()`；无内容缓存；无视口门控 | 多图表文档重复解析与布局 |
| 加载策略 | Excalidraw 工作区已 `defineAsyncComponent`；Mermaid 已动态 import | 包体积非主要问题 |
| 产物 | NSIS 6.3MB、exe 15MB、`dist/assets` 11MB JS | 无签名，SmartScreen 会提示 |
| 测试覆盖 | 24 个单测（document store、mermaidZoom、mermaidPreview、MermaidLightbox） | 无 E2E、无 Rust 侧测试 |

### 用户反馈状态

截至本文档，**尚无实际故障报告**。因此路线内容来自已知限制与代码中可测量的隐患，不虚构需求。凡无法测量的问题，先建基线再动手。

### 非目标（本路线明确不做）

- 云同步、多人协作、插件系统、移动客户端、遥测
- 购买商业代码签名证书
- 与本主轴无关的大规模重构

## 二、路线形状

**形状 A：小步快跑，一版一个主题**（已采纳）

| 版本 | 主题 | 依赖 |
| --- | --- | --- |
| 2.1.0 | 发布成果，信任底座起步 | 无 |
| 2.2.0 | 文件安全与系统集成 | 2.1 的 CI |
| 2.3.0 | 自动更新与性能 | 2.1 的 CI、2.2 的原子写入 |
| 3.0.0 | 扩张（主题待定） | 由真实反馈决定 |

被否决的形状：一次性大版本（反馈周期长、风险集中）；双轨并行（精力分散，与「安静可靠」定位冲突）。

每版 4–6 周，独立可发布。任何数据丢失类缺陷走 **hotfix 通道**，立即发 2.x.y 补丁，不等版本主题。

## 三、版本范围

### 2.1.0 — 发布成果，信任底座起步

- 发布 Mermaid 放大查看：悬停「放大查看」按钮或点击图表打开全屏灯箱；滚轮以光标为中心缩放、按钮 ±25%、适配窗口、100% 复位、拖拽平移、Esc 与关闭按钮退出、百分比显示
- 修复 `AppTitlebar` 中 `boolean | undefined` 赋值错误（`vue-tsc` 拦截）
- 建立 CI 最小闭环：`test` + `vue-tsc` + `vite build` + Tauri 打包 + 产出 SHA256 校验和
- README 增加无签名安装指引：SmartScreen 具体步骤与校验和比对方法
- 无障碍基线审计（对齐 PRODUCT.md 的 WCAG AA 承诺）：键盘可达性、焦点可见性、对比度、语义与标签；修 P0 项
- 版本号同步：`package.json`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json`、README 下载文件名、CHANGELOG

**完成标准**：测试与构建全绿；CI 产出安装包与校验和；干净 Windows 环境完整安装一次；文档三处版本号一致。

### 2.2.0 — 文件安全与系统集成

- 原子写入：同目录临时文件 → 写入 → fsync → rename 替换；保留上一版备份
- 草稿日志与崩溃恢复：未保存内容在下次启动时可恢复
- 外部修改检测：mtime 比对 + 冲突提示（重新载入 / 覆盖 / 另存为）
- 失败显式化：只读文件、磁盘满、路径越界均给出明确且可恢复的反馈
- 系统集成：`.md`/`.markdown` 文件关联 + 单实例 + 命令行参数与拖拽打开文件

**完成标准**：写入中断有可复现测试证明原文件不丢数据；双击 `.md` 直接进入应用；外部修改能弹出冲突处理。

**实现注意**：`tauri.conf.json` 的文件关联 `description` 必须是 ASCII。MSI 数据库使用代码页 1252（en-US），写入中文会让 WiX 的 `light.exe` 报 `LGHT0311`，表现为「failed to run light.exe」且 Tauri 不回显真实原因。排查方式：手动执行
`light.exe -ext WixUIExtension -ext WixUtilExtension -cultures:en-US -loc locale.wxl -out test.msi main.wixobj`（产物在 `src-tauri/target/release/wix/x64/`）。

另外两点经验：本地打包必须提供更新签名私钥，否则构建在签名阶段失败（`npm run release` 会自动从 `~/.markfx` 载入）；Windows 上刚生成的 `markfx.exe` 可能被杀软或索引器短暂占用，出现 `os error 32`，重试即可。

### 2.3.0 — 自动更新与性能

- 接入 Tauri updater + 更新包签名（免费 minisign 密钥，与 Windows 代码签名无关）
- 静态更新清单 + 应用内检查、通知、下载、安装与发布说明展示
- 性能：先建基线，再修实测问题
  - Mermaid 渲染结果按内容与主题缓存、并发去重、`initialize` 只执行一次（替代此前每次调用都重新初始化并重新渲染的做法）
  - 工具栏与公式提示的可访问名观察器改为 rAF 批处理，并只在与目标容器相关时才执行查询

**性能结论（实测记录）**：Milkdown 的代码块本身已经按视口懒初始化（`@milkdown/components` 的 `visibilityCallbacks` 与共享 IntersectionObserver：未进入视口时只渲染 `<pre>` 占位，进入视口才初始化 CodeMirror 并触发预览渲染）。因此**不再自行增加视口门控**，避免与上游机制重复；优化集中在重复渲染场景（编辑器重挂载、文档编辑反复触发 `renderPreview`）。

**基线限制说明**：本次未能采集浏览器级耗时基线——可用的浏览器自动化环境没有真实视口，IntersectionObserver 不触发，编辑器的代码块不会初始化，因而无法驱动端到端渲染测量。改为以可复现的量化守卫记录收益：8 张不同图表重复请求 40 次时，实际渲染次数由 40 次降为 8 次（见 `mermaidRender.test.ts`）。视口级耗时基线留待具备真实窗口的环境补齐。

**完成标准**：基线数据入库；每项优化给出前后对比数字；从 2.2.0 升级到 2.3.0 走通一次真实更新。

### 3.0.0 — 扩张（主题待定）

候选主题：多标签/多窗口、全文检索与替换、导出 PDF/HTML、macOS/Linux、插件系统。同时给出配置与数据格式的兼容承诺。主题由真实使用反馈决定，不在本路线中预设。

## 四、次要轨道（不定义版本）

表格编辑、粘贴 HTML 转 Markdown、图片拖入、Excalidraw 导出 PNG 嵌入文档、GitHub Issue 模板用于收集反馈。

## 五、每版完成定义（DoD）

1. 新增行为有测试，且测试先失败后通过
2. `npm test` 与 `npm run build`（含 `vue-tsc`）全绿
3. 干净 Windows 环境实测安装与启动
4. CHANGELOG、README、PRODUCT.md 与版本号一致
5. 发布说明包含校验和与已知限制
6. 数据安全类改动必须有可复现的故障注入验证

### 记录未修（P1，留待后续）

- 代码块的语言选择器提供 143 个 CodeMirror 模式，但**不含 Mermaid**：已有代码块无法通过选择器切换为 Mermaid 图表，只能依靠 ```` ```mermaid ```` 围栏输入规则。后续版本应让 Mermaid 出现在选择器中，或提供快捷入口。
- 代码块的 `Text`、`Copy`、`Hide` 等控件文案为 Crepe 默认英文，未随界面本地化。
- 工具栏标签按位置下标分配（`toolbarHints` 数组顺序）。增删工具栏项会静默错位，宜改为按命令键映射。
- 大纲折叠/展开按钮的焦点环使用负偏移（`outline-offset: -2px`），与元素边缘重叠，在强调色背景上可辨识度偏低。

## 七、风险

| 风险 | 缓解 |
| --- | --- |
| 无签名导致用户流失 | README 明确指引 + 校验和 + 可验证构建；后续评估证书 |
| 更新包被篡改 | updater 强制验证 minisign 签名，公钥内置 |
| 性能优化无据可依 | 强制先建基线与前后对比 |
| 崩溃恢复引入新数据风险 | 草稿与正式文件分离；恢复操作可撤销 |
| 范围蔓延到扩张主题 | 扩张一律推迟到 3.0，按真实反馈选题 |
